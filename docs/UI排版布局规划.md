# EchoMem UI 排版布局规划

> 日期：2026-05-11
> 目标：让观测台信息架构更清晰，减少单页信息拥挤，并允许用独立页面承载不同观察任务。

## 1. 当前布局问题

当前 UI 只有两个一级入口：

- 会话
- 观测台

「观测台」内部再通过 tabs 承载检索、记忆框架、画像、能力观测。这个结构可用，但随着三框架整合、知识图谱、画像演化、能力指标逐渐增多，信息密度开始偏高：

- 用户想看“三框架效果”时，需要先进入观测台，再切 tab。
- 检索统计、记忆时间线、框架实验室、用户画像都在同一页面上下文里，心智模型不够清楚。
- 每个 tab 内容都较长，横向 tab 不适合继续增加新视图。

## 2. 新信息架构

把原「观测台」拆成多个一级页面：

| 一级页面 | 主要用途 | 内容边界 |
|---|---|---|
| 会话 | 和助手对话 | 聊天、建议问题、本轮演化折叠信息 |
| 总览 | 快速判断系统状态 | 运行环境、记忆统计、最近检索、记忆时间线 |
| 记忆框架 | 比较三框架效果 | Mem0 / LlamaIndex / Cognee 通道、写回状态、知识图、MiMo 分析 |
| 用户画像 | 查看用户状态变化 | 当前画像、画像更新、画像历史、演化时间轴 |
| 系统能力 | 调试编排能力 | STM/LTM、情绪、工具调用、能力指标 |

## 3. 排版原则

- 一级页面只承载一个核心观察任务，避免“一个页面解释所有东西”。
- 每页首屏先展示结论型信息，再展示表格和 JSON。
- 数据表只作为明细层，不再作为首屏表达主角。
- 重要路径保持稳定：会话产生数据，其他页面解释数据。
- 移动端优先保持单列阅读，桌面端使用左右分栏。

## 4. 页面布局草图

### 会话

```text
顶部会话标题
欢迎卡 / 聊天线程
本轮画像与记忆演化（折叠）
输入框
```

### 总览

```text
Masthead
检索可解释性（左） | 检索仪表盘（右）
记忆时间线
时间衰减驱动检索（有本轮命中时显示）
```

### 记忆框架

```text
Masthead
记忆实验室仪表盘
框架信号明细（左） | 用户知识体系图（右）
MiMo / DeepSeek 知识分析
原始 JSON（折叠）
```

### 用户画像

```text
Masthead
画像快照
本轮演化轨迹
画像变化记录
画像演化时间轴
```

### 系统能力

```text
Masthead
能力指标
长短期记忆协同（左） | 情绪与风格调节（右）
工具调用能力
```

## 5. 本轮构建范围

- 侧边栏导航从 2 个入口扩展为 5 个一级页面。
- 移除观测台内部四个大 tab 的主路径依赖。
- 保留原有数据展示能力，不删除检索、框架、画像、能力内容。
- 更新端到端手册中观测台路径说明。

## 6. 验收标准

- 用户能从侧边栏直接进入「总览 / 记忆框架 / 用户画像 / 系统能力」。
- 每个页面只展示该主题最相关的内容。
- 三框架实验室页面仍能展示形象化通道卡。
- `python -m unittest discover tests -v` 通过。
- `python scripts/workflow.py` 通过。
