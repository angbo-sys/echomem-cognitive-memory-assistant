# NeuroMate 技术规划文档

## 1. 项目定位与目标

### 1.1 项目定位
NeuroMate 是一个“长期陪伴型学习 Agent”，核心不在单次问答质量，而在持续交互中形成并演化对用户的认知。

### 1.2 总体目标
构建一个具备以下能力的可扩展系统：
- 长短期记忆协同
- 用户画像持续演化
- 时间衰减驱动的记忆检索
- 情绪感知与回复风格调节
- 工具调用能力（学习计划、检索、复习建议）
- 云端与本地模型统一接入

### 1.3 成功标准（Definition of Done）
- 能稳定运行 Day1~Day30 的连续对话数据。
- 在 Proposed 方案上，`Preference Accuracy`、`Persona Consistency`、`Emotional Alignment` 均优于 Baseline A/B/C。
- UI 可完整展示 Memory Timeline、Retrieval Dashboard、画像变化。
- 提供失败案例复盘与可解释日志。

---

## 2. 技术路线总览

### 2.1 路线原则
- 先可用，后增强：先打通端到端闭环，再优化检索质量与成本。
- 模块解耦：Memory/Profile/LLM/Agent 分层，接口稳定。
- 可替换：向量库、Embedding、LLM 统一抽象，支持后续切换。
- 可评估：每个模块有可观测指标与日志。

### 2.2 分阶段技术路线
1. Phase 0：系统骨架与统一接口
2. Phase 1：STM + LTM 基础能力
3. Phase 2：Profile Engine + Emotion Engine
4. Phase 3：时间感知检索 + 冲突记忆更新
5. Phase 4：Tool Calling + Prompt Fusion
6. Phase 5：实验评测、可视化、失败案例复盘

---

## 3. 系统架构设计

### 3.1 架构流程
用户输入 → Agent Orchestrator → STM/LTM/Profile/Emotion → Memory Engine（打分排序）→ Retrieval Fusion → LLM Adapter → 响应生成

### 3.2 模块分层
- `agent/`：编排层（流程控制、工具路由、Prompt 组装）
- `memory/`：记忆层（存储、召回、打分、冲突处理）
- `profile/`：用户画像与情绪层
- `llm/`：模型适配层（OpenAI/Qwen/Ollama）
- `database/`：SQLite 与向量索引持久化
- `ui/`：Streamlit 展示层
- `dataset/`：30天连续交互样本
- `experiments/`：基线与指标评测脚本

### 3.3 关键接口约束
- `BaseLLM.generate(prompt, **kwargs) -> str`
- `MemoryStore.add(memory_item)`
- `MemoryRetriever.search(query, top_k) -> list[MemoryHit]`
- `ProfileManager.update(event)`
- `EmotionEngine.classify(text) -> EmotionState`

## 4. 详细模块方案

### 4.1 短期记忆（STM）
- 实现：`ConversationBufferMemory`（首版）+ `ConversationSummaryMemory`（长上下文时自动压缩）。
- 策略：保留最近 N 轮（建议 N=6~10），超过阈值触发摘要。
- 输出：`recent_dialogue` + `summary_context`。

### 4.2 长期记忆（LTM）
- 存储对象：
  - 历史问题
  - 偏好声明
  - 学习目标与变化事件
  - 高情绪强度事件
- 向量库：开发期 Chroma（易调试），评测期可切 FAISS（性能稳定）。
- Embedding：`bge-small-zh` 默认，保留 `text2vec` 切换配置。

### 4.3 用户画像（Profile Engine）
- SQLite 表设计：
  - `user_profile_current`：当前画像快照
  - `user_profile_history`：历史变更日志（字段、旧值、新值、时间、置信度）
- 更新策略：
  - 明确表达优先（如“以后简短回答”）
  - 高重要度事件触发覆盖
  - 历史保留，不直接删除

### 4.4 情绪感知（Emotion Engine）
- 类别：`positive/neutral/anxious/frustrated/confident`
- 方案：
  - 首版：LLM Prompt 分类（快速上线）
  - 增强：引入轻量分类器做二次校验
- 风格映射：
  - `anxious`：鼓励+分步骤+低信息密度
  - `frustrated`：先共情，再给可执行动作
  - `confident`：提高信息密度，减少安抚语

### 4.5 时间感知记忆检索
- 核心公式：

```text
Score = Similarity × Importance × exp(-λt)
```

- 参数建议：
  - `Similarity`：向量余弦相似度（0~1）
  - `Importance`：LLM评分（0~1）
  - `t`：天级时间差
  - `λ`：0.02~0.08（通过验证集网格搜索）
- 实现流程：
  1. 向量召回 Top-K（如 20）
  2. 读取 importance 与时间戳
  3. 计算衰减分并重排
  4. 输出最终 Top-M（如 5）

### 4.6 记忆重要性评分
- 评分维度：考试、焦虑、长期目标、偏好变更、失败/突破事件。
- 实现：Prompt 打分 + 规则兜底（关键词与模式匹配）。
- 输出结构：

```json
{
  "memory": "...",
  "importance": 0.92,
  "reason": "涉及考试与长期目标"
}
```

### 4.7 冲突记忆更新（Memory Evolution）
- 检测条件：同一画像字段出现语义对立新证据。
- 处理动作：
  - 旧记忆 `status=deprecated`
  - 旧记忆 importance 衰减（如乘 0.3）
  - 新偏好写入 `user_profile_current`
  - 在 `user_profile_history` 记录冲突解决链路

### 4.8 Retrieval-Augmented Prompt Fusion
- Prompt 组成：
  - 当前问题
  - STM 摘要与最近轮次
  - LTM 重排 Top-M
  - 当前画像
  - 当前情绪
- 防污染策略：
  - 对“过期/冲突记忆”加标记，不默认注入主上下文
  - 生成前做 token 预算裁剪

### 4.9 Tool Calling Agent
- 最少 3 个工具（建议 4 个）：
  - `StudyPlannerTool`
  - `MemorySearchTool`
  - `EmotionAnalyzer`
  - `ReviewGenerator`
- 编排方式：
  - LangChain Tool Calling（主流程）
  - Function Calling schema 严格定义输入输出
  - 异常兜底：工具失败回退纯 LLM 方案

### 4.10 统一模型适配层
- 接口：
  - `BaseLLM`
  - `OpenAIAdapter`
  - `QwenAdapter`
  - `OllamaAdapter`
- 配置管理：`.env + yaml`，支持模型切换、温度、最大 token、超时、重试。
- 目标：上层编排不感知底层模型提供方。

## 5. 数据与存储设计

### 5.1 SQLite 建议表
- `conversations(id, user_id, role, content, ts)`
- `memories(id, user_id, content, type, importance, status, source, ts)`
- `profile_current(user_id, learning_goal, preferred_style, weak_subject, emotion_state, knowledge_level, recent_focus, updated_at)`
- `profile_history(id, user_id, field, old_value, new_value, trigger, confidence, ts)`
- `retrieval_logs(id, user_id, query, memory_id, similarity, decayed_score, ts)`

### 5.2 向量索引
- 文档粒度：1~3 句记忆切片。
- 元数据：`memory_id/type/importance/status/ts`。
- 同步策略：写入 SQLite 成功后再写入向量库，失败重试并记录死信。

## 6. 实验与评测方案

### 6.1 Baseline 设计
- A：无记忆
- B：仅 STM
- C：普通向量记忆（无时间衰减、无冲突更新）
- Proposed：完整认知记忆系统

### 6.2 指标计算
- `Recall@K`：关键历史事件是否被召回
- `Preference Accuracy`：回复是否符合当前偏好
- `Persona Consistency`：跨天风格稳定性
- `Emotional Alignment`：情绪与回复风格匹配率
- `Token Cost`：每次请求平均 token
- `Response Coherence`：人工+LLM评审一致性

### 6.3 实验流程
1. 构建 Day1~Day30 数据集
2. 跑 4 组系统对照
3. 记录日志与指标
4. 分析失败案例并回放检索链路

## 9. 风险与应对

- 检索噪声高：提高记忆切片质量，加入规则过滤与重排。
- 情绪误判：LLM+规则双通道，低置信度回退 neutral。
- 成本波动：摘要压缩、Top-K 裁剪、缓存高频结果。
- 画像漂移：只允许高置信度事件覆盖 current，保留审计日志。
- 工具不稳定：工具超时熔断并回退纯问答。
