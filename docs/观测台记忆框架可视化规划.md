# 观测台记忆框架可视化规划

> 日期：2026-05-11
> 目标：让 Mem0 / LlamaIndex / Cognee 的观察数据更形象、更可解释，并能直接反映不同记忆框架的效果差异。

## 1. 现状问题

当前「观测台 → 记忆框架」已经能展示 `framework_contributions` 和 `framework_writes`，但主要形态仍是卡片、柱状图和表格。它能说明“有数据”，但对非技术用户不够直观：

- Mem0、LlamaIndex、Cognee 的角色差异需要读表格字段才能理解。
- 命中信号、写回状态、Prompt 注入之间的关系没有形成完整视觉链路。
- 原始 JSON 对调试有用，但不适合作为第一层观察界面。

## 2. 设计方向

采用“记忆实验室仪表盘”视觉：把三套框架表现为三条不同的认知通道。

- Mem0：偏向“用户偏好/画像事实”，呈现为个人事实通道。
- LlamaIndex：偏向“文档/会话知识命中”，呈现为知识证据通道。
- Cognee：偏向“知识图谱关联概念”，呈现为关系网络通道。

页面第一眼要回答三个问题：

- 哪个框架这轮贡献最大？
- 每个框架贡献了什么类型的记忆？
- 这轮对话是否已经写回到对应框架？

## 3. 数据映射

| 数据字段 | 视觉表达 | 用户理解 |
|---|---|---|
| `framework_contributions[].framework` | 三张框架通道卡 | 当前是哪套记忆框架 |
| `role` | 卡片副标题 | 这套框架负责什么 |
| `signal_count` | 强度条 / 数字仪表 | 贡献信号多少 |
| `signals[]` | 信号胶囊 | 具体命中的记忆片段 |
| `signal_source` | 来源标签 | 来自云端、本地索引或 fallback |
| `framework_writes[framework].stored` | 写回状态灯 | 本轮对话是否进入长期记忆链路 |
| `scenario_routing.scenario` | 顶部场景胶囊 | 当前检索/记忆路由场景 |
| `query_expansion` | 查询扩展胶囊 | 三框架共同扩展出的提示词 |

## 4. 页面结构

1. 顶部摘要带：展示场景、查询扩展数量、写回成功数量。
2. 三框架通道卡：Mem0 / LlamaIndex / Cognee 分别显示角色、信号强度、来源和写回状态。
3. 记忆流向条：展示“用户输入 → 三框架观察 → Prompt/UI → 对话写回”的闭环。
4. 信号胶囊区：每个框架最多展示 4 条代表信号，避免信息过载。
5. 原始数据抽屉：保留 JSON，给调试和复核使用。

## 5. 构建范围

本轮只做前端展示增强，不改变记忆框架数据结构：

- 新增 `render_memory_framework_lab()` 组件。
- 替换观测台中原有的简单框架卡片/表格首屏。
- 保留知识图、MiMo 分析和原始 JSON。
- 新增组件级测试，保证 HTML 转义和核心信息渲染稳定。

## 6. 验收标准

- 观测台能以形象卡片展示三框架不同角色。
- 用户能直接看到每个框架的命中数量、信号预览、来源和写回状态。
- 原始 JSON 仍可展开查看。
- `python -m unittest discover tests -v` 通过。
- `python scripts/workflow.py` 通过。
