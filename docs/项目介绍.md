# EchoMem 项目介绍

> EchoMem 是一个“会记住你、会随你变化、还能把记忆过程展示出来”的 AI 学习助手。它不是只回答眼前这一句话，而是会结合你的目标、偏好、情绪、历史对话和知识背景，给出更贴近个人状态的回答。

---

## 1. 一句话说明

EchoMem 可以理解为一个带“长期记忆”和“观察仪表盘”的 AI 学习伙伴。

普通聊天工具更像一次性问答：你问什么，它答什么。EchoMem 更像一个逐渐熟悉你的学习助理：它会记住你正在准备什么、偏好怎样的讲解方式、哪些知识点反复卡住、最近关注什么，并在后续对话里主动利用这些信息。

同时，EchoMem 不把这些记忆藏在黑箱里。它提供了可视化界面，让使用者看到系统到底检索了哪些记忆、识别了什么画像、调用了哪些记忆框架、哪些内容被写回了长期记忆。

---

## 2. 它解决什么问题

很多 AI 助手在学习场景里有三个常见问题：

1. **不记得人**
   用户上周说过“我在准备考研英语”，今天再问阅读题，它仍然像第一次见面一样回答。

2. **不理解变化**
   用户的目标、薄弱点和偏好会变化。比如从“数学建模”转向“考研数学”，从“想要详细解释”变成“只要步骤和结论”。普通系统很难管理这种变化。

3. **不知道依据**
   AI 给了建议，但用户看不到它用了哪些历史信息，也不知道哪些记忆影响了回答。

EchoMem 的设计重点就是补上这三件事：

- 让助手长期记住用户。
- 让记忆能更新、能废弃旧信息。
- 让记忆检索和使用过程可观察、可验证。

---

## 3. 适合谁使用

EchoMem 适合以下几类使用者：

- **学生或自学者**：希望 AI 能持续跟踪学习目标、错题、薄弱点和复习计划。
- **教师或学习产品设计者**：想观察 AI 如何根据用户画像生成个性化辅导。
- **AI Agent 研究者**：需要一个可测试、可观察的记忆型 Agent 原型。
- **产品经理或演示人员**：需要展示“长期记忆 AI 助手”如何工作，而不是只展示一次性问答。
- **开发者**：想比较 Mem0、LlamaIndex Memory、Cognee 等记忆框架在同一产品中的作用差异。

## 4. 用户能直接感受到什么

### 4.1 它会记住长期目标

如果用户说：

> “研究生是我接下来的方向。”

EchoMem 会把它理解为学习目标，而不是普通闲聊。后续当用户问复习计划、知识点解释或学习进度时，它会把这个目标作为背景。

### 4.2 它会记住讲解偏好

如果用户说：

> “讲题时请一步一步拆开讲。”

系统会把“分步骤讲解”记录为偏好。之后回答时，它会更倾向于按步骤组织内容。

### 4.3 它会识别薄弱点

如果用户说：

> “概率论总是卡住。”

系统会把“概率论”识别为薄弱领域。后续做学习计划、复习建议或知识解释时，会优先关注这个点。

### 4.4 它会理解当前状态

EchoMem 能识别用户当前情绪，例如焦虑、困惑、疲惫、好奇、沮丧等。它不会只机械回答问题，而是可以根据情绪调整语气和建议方式。

### 4.5 它能展示“为什么这样回答”

在观测台中，用户可以看到：

- 这轮回答检索到了哪些历史记忆。
- 哪些用户画像被更新了。
- 三个记忆框架分别贡献了什么内容。
- 哪些对话内容被写回长期记忆。
- 系统能力链路是否正常。

## 6. 五个核心页面

EchoMem 的界面不是一个简单聊天框，而是一个“认知记忆观测台”。当前包括五个一级页面。

### 6.1 会话

这是用户和 EchoMem 对话的主入口。

用户可以：

- 直接提问。
- 使用建议问题快速开始。
- 切换任务模式，例如常规对话、学习计划、复习建议。
- 新建不同会话。
- 在同一用户下切换历史会话。
- 清空当前会话。

会话页会展示当前回复，以及本轮画像更新和记忆演化摘要。

### 6.2 总览

总览页用于快速了解系统当前状态。

这里可以看到：

- 当前记忆库概况。
- 最近检索到的记忆。
- 主动记忆搜索台。
- 检索结果的相似度、重要性和时间衰减信息。
- 记忆组成和时间线。

简单说，它回答的是：

> “系统现在记住了什么？能不能搜到有用内容？”

### 6.3 记忆框架

这一页展示 Mem0、LlamaIndex Memory、Cognee 三个记忆框架分别做了什么。

它回答的是：

- Mem0 记住了哪些用户偏好和个人事实？
- LlamaIndex 命中了哪些会话或文档知识？
- Cognee 找到了哪些知识图谱关系？
- 哪些框架真的返回了有价值内容？
- 这轮对话是否写回了这些框架？

这对开发者和评估人员尤其重要，因为它能区分“接入了框架”和“框架真的发挥了作用”。

### 6.4 用户画像

用户画像页展示 EchoMem 对用户的当前理解。

包括：

- 学习目标
- 偏好风格
- 薄弱科目
- 知识水平
- 近期关注
- 情绪状态
- 画像演化历史

例如用户从“准备英语阅读”转向“准备考研数学”，系统会记录变化，并把旧记忆标记为过时或降低权重。

### 6.5 系统能力

系统能力页用于展示内部链路是否正常。

例如：

- 短期记忆是否工作。
- 长期记忆是否工作。
- 情绪识别是否工作。
- 检索工具是否工作。
- 模型路由是否工作。
- 记忆写回是否工作。

这相当于 EchoMem 的“健康状态面板”。

## 7. EchoMem 怎么“记住人”

EchoMem 的记忆不是一整段混乱的聊天记录，而是分成几类来管理。

### 7.1 短期记忆

短期记忆记录当前会话里最近发生的事情，类似“这次聊天的上下文”。

当前已经支持：

- 保存最近多轮对话。
- 按用户隔离。
- 按会话隔离。
- 列出会话标题、消息数和更新时间。
- 在 UI 中新建、切换和清空会话。

### 7.2 长期记忆

长期记忆记录更稳定的信息，例如：

- 用户目标
- 用户偏好
- 重要知识点
- 历史学习记录
- 已确认的薄弱点

长期记忆支持检索、排序、状态管理和过时记忆处理。

### 7.3 用户画像

用户画像是对用户状态的结构化总结。

当前重点画像字段包括：

- `learning_goal`：学习目标
- `preferred_style`：讲解偏好
- `weak_subject`：薄弱领域
- `knowledge_level`：知识水平
- `recent_focus`：近期关注
- `emotion_state`：情绪状态

EchoMem 不只识别“我的目标是考研数学”这种固定句式，也能识别更自然的表达，例如：

- “研究生是我接下来的方向。”
- “概率论总是卡住。”
- “讲题时请一步一步拆开讲。”
- “我零基础。”
- “最近一直刷贝叶斯公式和条件概率。”

## 8. 三个记忆框架分别做什么

EchoMem 同时整合了三类记忆框架。它们不是重复做同一件事，而是各自承担不同角色。

| 框架 | 可以理解为 | 主要负责 |
| --- | --- | --- |
| Mem0 | 用户事实和偏好记忆 | 记住“用户喜欢什么、目标是什么、稳定事实是什么” |
| LlamaIndex Memory | 会话和文档知识记忆 | 找到与问题相关的历史对话、学习材料、文档片段 |
| Cognee | 知识图谱和关系联想 | 找到知识点之间的关系，例如“条件概率”和“贝叶斯公式”的关联 |

### 8.1 Mem0

Mem0 更像“个人事实记忆库”。

它适合保存：

- 用户偏好
- 长期目标
- 稳定事实
- 学习习惯

### 8.2 LlamaIndex Memory

LlamaIndex Memory 更像“会话和文档上下文记忆库”。

它适合保存：

- 历史对话片段
- 学习材料内容
- 解析后的文档知识
- 与当前问题相关的知识证据

项目已接入 LlamaCloud / LlamaParse，用于把文本或文档解析成可用上下文。

### 8.3 Cognee

Cognee 更像“知识关系网络”。

它适合发现：

- 哪些知识点经常一起出现。
- 某个概念和哪些概念有关。
- 用户薄弱点和学习目标之间有什么关系。

Cognee 支持云端和本地模式。当前项目默认优先使用已验证的云端链路；云端可用时会避免不必要的本地包初始化，减少测试日志噪音。

## 9. 一个典型使用流程

下面是一个普通用户可能经历的流程。

1. 用户打开 EchoMem。
2. 用户说：“研究生是我接下来的方向，概率论总是卡住，讲题时请一步一步拆开讲。”
3. EchoMem 识别出：
   - 学习目标：研究生
   - 薄弱领域：概率论
   - 偏好风格：分步骤
4. 系统把这些信息写入用户画像和长期记忆。
5. 用户继续问：“帮我规划一下这周怎么复习。”
6. EchoMem 会结合目标、薄弱点、偏好和历史记忆，生成更贴合个人状态的计划。
7. 在观测台中，用户可以看到这轮回答用到了哪些记忆和框架信号。

## 11. API 配置如何管理

EchoMem 现在把主要 API 配置统一交给一个配置中心读取。可以把它理解成“系统启动前先整理一张服务通讯录”，后面的对话模型、记忆分析和记忆框架都从这张通讯录拿地址和凭证。

当前统一管理的对象包括：

- 对话模型：MiMo、DeepSeek、OpenAI、Qwen、Ollama
- 记忆分析模型：用于辅助知识分析和检索增强
- 记忆框架云端服务：Mem0、LlamaCloud、Cognee Cloud
- 检索和运行参数：检索后端、超时、温度、最大输出长度等

配置读取优先级是：

1. 当前运行环境变量
2. 本地 `.env` 文件
3. `config/settings.toml` 默认配置

这样做的好处是：开发时可以把本机密钥和 API 地址放在 `.env`，部署时可以用环境变量覆盖，`settings.toml` 只保留非敏感默认结构和产品参数，便于阅读和调整。界面中只显示“API 已配置 / API 未配置”，不会展示具体密钥。

常用配置文件：

| 文件 | 作用 |
| --- | --- |
| `.env.example` | API 配置模板，复制成 `.env` 后填写本机密钥 |
| `.env` | 本地私有配置，通常不提交 |
| `config/settings.toml` | 非敏感默认模型、检索和记忆框架参数 |
| `config/loader.py` | 统一读取并合并配置 |
| `config/factory.py` | 根据统一配置创建模型和记忆系统 |

检查配置是否就绪：

```bash
conda run -n echomem-test python scripts/check_memory_frameworks_env.py
```

## 12. 和普通聊天机器人有什么不同

| 对比点 | 普通聊天机器人 | EchoMem |
| --- | --- | --- |
| 是否记住用户 | 通常只依赖当前上下文 | 有短期记忆、长期记忆和用户画像 |
| 是否理解用户变化 | 较弱 | 支持画像演化和旧记忆废弃 |
| 是否能解释依据 | 通常不可见 | UI 展示检索命中、框架贡献和写回状态 |
| 是否能比较记忆框架 | 不能 | 同时展示 Mem0、LlamaIndex、Cognee 的作用 |
| 是否适合研究和演示 | 需要额外搭建 | 内置测试、评测、观测台和文档 |
| 是否面向学习场景 | 不一定 | 明确围绕学习目标、薄弱点、复习计划设计 |

## 13. 非技术版架构说明

可以把 EchoMem 想象成一个由五个部分组成的学习助理团队。

1. **接待员：对话界面**
   负责接收用户输入，并把回答展示出来。

2. **笔记员：短期和长期记忆**
   负责记录当前会话和重要长期信息。

3. **画像师：用户画像**
   负责总结用户是谁、目标是什么、偏好是什么、哪里薄弱。

4. **资料员：记忆检索和三框架系统**
   负责在回答前查找相关历史信息和知识关系。

5. **主讲老师：大模型**
   负责综合所有信息，生成最终回复。

大致流程如下：

```text
用户提出问题
  ↓
系统读取当前会话、长期记忆、用户画像和情绪
  ↓
检索相关历史记忆
  ↓
调用 Mem0 / LlamaIndex / Cognee 获取不同类型的记忆信号
  ↓
整理成适合大模型理解的上下文
  ↓
大模型生成回答
  ↓
系统更新记忆、画像和观测台状态
```

## 15. 当前限制

EchoMem 已经具备完整原型能力，但还不是最终产品。当前仍有一些后续增强方向：

- UI 自动截图回归暂未接入，视觉问题仍主要依赖人工验收。
- LLM 回复还不是逐字流式输出，长回答需要等待完整生成。
- Orchestrator 仍偏集中式，后续可以拆成更清晰的 Pipeline。
- API、模型和记忆框架配置已统一；仍有少量 UI 尺寸、Prompt 权重等产品参数后续可继续集中治理。
- 会话历史已支持基础切换，后续还可以增加重命名、归档、全文搜索。
- 三框架云端/本地模式主要通过配置控制，UI 中还没有完整可视化切换面板。
- Cognee 本地模式仍可能输出包级初始化横幅和少量资源警告，但已跳过误导性的连接探测。

这些限制不影响当前核心链路演示和本地交付验证。

## 18. 总结

EchoMem 是一个面向学习场景的记忆型 AI 助手原型。它的核心价值不是“多接几个模型”，而是让 AI 能持续理解一个人：记住目标、识别偏好、发现薄弱点、跟踪变化，并把这些过程清楚地展示出来。

它适合用来演示和研究下一代 AI 助手应该如何“记得住、看得见、可验证、可演化”。
