# EchoMem 端到端记忆测试手册

> 最后更新：2026-05-11  
> 当前基线：`echomem-test` 环境，101 个单元/集成测试通过，`scripts/workflow.py` 通过  
> 测试目标：从空库开始验证 EchoMem 的核心记忆链路，并用当前完整测试矩阵确认项目可交付。

---

## 1. 测试目标

本文档用于复现 EchoMem 的端到端记忆测试流程。它覆盖从“空数据库”开始的真实链路验证，也覆盖当前项目的完整回归测试。

本手册要确认：

- 长期记忆可以写入、检索、按用户隔离。
- 短期记忆可以参与当前会话上下文。
- 用户画像可以抽取、更新、记录历史，并触发旧画像记忆废弃。
- 同一问题在不同用户记忆下会产生不同回复。
- Chroma 持久化向量检索、SQL fallback、中文 N-gram + BM25-like 排序仍可用。
- Mem0 / LlamaIndex Memory / Cognee 三框架贡献摘要和写回链路仍可用。
- UI 观测台五个一级页面可以展示检索、记忆框架、画像和系统能力。
- 项目全量测试和交付工作流仍通过。

## 2. 当前测试范围

### 2.1 自动化 E2E 覆盖

自动化 E2E 脚本会执行：

- 清空长期记忆库 `memory.db`。
- 清空画像库 `profile/profile.db`。
- 从空库创建两个测试用户：`e2e_reader` 与 `e2e_math`。
- 模拟 5 轮对话，覆盖目标、薄弱点、回答偏好、压力情绪、目标冲突。
- 验证同一问题在不同用户记忆下输出不同。
- 验证检索按 `user_id` 隔离，不串用户记忆。
- 验证画像更新写入 `profile_current` 与 `profile_history`。
- 验证记忆冲突会废弃旧 `profile_field` 记忆并写入新记忆。
- 验证开源记忆框架提示结构可用。
- 写入报告：`.context/e2e-fresh-run/e2e_report.json`。

### 2.2 当前完整回归覆盖

除 E2E 脚本外，当前完整回归还必须覆盖：

- `python -m unittest discover tests -v`：101 个测试全部通过。
- `python scripts/workflow.py`：编译检查、单元测试、Baseline 评测全部通过。
- `scripts/check_memory_frameworks_env.py`：检查 Mem0 / LlamaIndex / Cognee / Chroma / LlamaCloud 相关环境状态。
- 数据库污染检查：正式库不应出现 `user_id is null` 或 `source='t'` 的单测污染数据。
- UI 人工验收：五个一级页面均可打开，且关键观测数据展示合理。

## 3. 重要提醒

以下步骤会删除当前运行数据：

- `memory.db` 中所有记忆。
- `profile/profile.db` 中所有当前画像和画像历史。
- `.context/e2e-fresh-run/e2e_report.json` 会被新报告覆盖。

执行前请确认不需要保留当前本地记忆数据。如果需要备份，可先运行：

```bash
mkdir -p .context/backups
cp memory.db .context/backups/memory.$(date +%Y%m%d-%H%M%S).db
cp profile/profile.db .context/backups/profile.$(date +%Y%m%d-%H%M%S).db
```

## 4. 推荐测试顺序

建议按以下顺序执行：

1. 运行端到端空库记忆测试。
2. 查看 E2E 报告摘要。
3. 检查数据库计数和污染数据。
4. 运行全量单元/集成测试。
5. 运行交付工作流。
6. 运行记忆框架环境检查。
7. 启动 UI 并按人工验收清单检查五个页面。

## 5. 自动化端到端测试

在项目根目录执行：

```bash
conda run -n echomem-test python .context/e2e-fresh-run/e2e_fresh_memory_test.py
```

该脚本会调用真实项目模块：

- `LongTermMemory`
- `ProfileManager`
- `MemorySearch`
- `Orchestrator`
- `EmotionAnalyzer`

脚本使用确定性的本地测试 LLM，避免消耗外部 API，并让记忆影响可重复验证。

成功时，报告中的 `passed` 应为 `true`。

## 6. E2E 核心测试场景

| 阶段 | 用户 | 输入 | 主要验证点 |
| --- | --- | --- | --- |
| reader_onboarding | `e2e_reader` | 我的目标是考研英语，薄弱的是阅读理解，请简洁分步骤回答。 | 建立英语阅读画像、偏好简洁分步骤 |
| math_onboarding | `e2e_math` | 我的目标是数学建模，薄弱的是概率论，请详细举例回答。 | 建立数学建模画像、偏好详细举例 |
| same_query_reader_memory_influence | `e2e_reader` | 我今天压力很大，给我一套训练建议。 | 同一问题受英语阅读记忆影响 |
| same_query_math_memory_influence | `e2e_math` | 我今天压力很大，给我一套训练建议。 | 同一问题受数学建模记忆影响 |
| reader_conflict_evolution | `e2e_reader` | 我的目标是雅思阅读，薄弱的是长难句，请详细举例回答。 | 触发目标、偏好、薄弱点冲突演化 |

## 8. 数据库验收

自动化测试完成后，检查数据库计数：

```bash
conda run -n echomem-test python - <<'PY'
import sqlite3

for db in ["memory.db", "profile/profile.db"]:
    con = sqlite3.connect(db)
    print("\n" + db)
    for row in con.execute("select name from sqlite_master where type='table'"):
        table = row[0]
        if table == "sqlite_sequence":
            continue
        print(table, con.execute(f"select count(*) from {table}").fetchone()[0])
    con.close()
PY
```

期望核心结果：

```text
memory.db
memories 25

profile/profile.db
profile_current 2
profile_history 15
```

同时检查没有单测污染正式库：

```bash
conda run -n echomem-test python - <<'PY'
import sqlite3

con = sqlite3.connect("memory.db")
print("null_user_rows", con.execute("select count(*) from memories where user_id is null").fetchone()[0])
print("source_t_rows", con.execute("select count(*) from memories where source='t'").fetchone()[0])
con.close()
PY
```

期望结果：

```text
null_user_rows 0
source_t_rows 0
```

## 11. UI 人工验收

启动 Streamlit：

```bash
conda run -n echomem-test streamlit run ui/app.py --server.headless true --server.port 8510
```

打开：

```text
http://localhost:8510/
```

### 11.1 会话

检查点：

- 左侧 `User ID` 下拉框应包含 `e2e_reader` 与 `e2e_math`。
- 默认会话页应正常显示欢迎卡片。
- 侧边栏应显示“快速回复模式（减少思考时间）”。
- 快速回复模式开启时，“开启 AI 知识分析”应被禁用或避免阻塞主流程。
- 对话输入框不应遮挡主体内容。
- 长回复卡片应完整展开，不应裁剪底部文字。

### 11.2 总览

路径：侧边栏选择 `📊 总览`。

检查点：

- `总记忆数` 应显示约 `25`。
- `活跃记忆` 应显示约 `20`。
- 能看到记忆组成图。
- 能看到检索命中卡片或最近记忆表。
- 记忆时间线图表应显示。
- 最近记忆应包含 `e2e_reader`、`e2e_math` 的对话和画像字段记忆。

### 11.3 记忆框架

路径：侧边栏选择 `🧬 记忆框架`。

检查点：

- 能看到 Mem0 / LlamaIndex / Cognee 三条记忆通道。
- 能看到每个框架的角色、信号强度、来源和信号预览。
- 能看到写回状态灯或写回结果。
- 能看到查询扩展胶囊。
- 如有知识图数据，能看到用户知识体系图或相关概念说明。

### 11.4 用户画像

路径：侧边栏选择 `👤 用户画像`。

选择 `e2e_reader` 时，应看到：

- `learning_goal` 包含雅思阅读。
- `preferred_style` 包含详细。
- `weak_subject` 包含长难句。
- `recent_focus` 包含压力训练建议。

画像演化时间轴应包含：

- 考研英语到雅思阅读的目标变化。
- 阅读理解到长难句的薄弱点变化。
- 简洁/分步骤到详细的偏好变化。

选择 `e2e_math` 时，应看到：

- `learning_goal` 包含数学建模。
- `weak_subject` 包含概率论。
- `recent_focus` 包含压力训练建议。

### 11.5 系统能力

路径：侧边栏选择 `🛠 系统能力`。

检查点：

- 能看到长期记忆、短期记忆、情绪识别、工具调用、模型路由等能力块。
- 能看到能力链路图。
- 情绪感知区域应显示情绪标签结构。
- 工具调用区域应说明当前任务模式。

## 13. 已知限制

当前已知限制不阻断本地交付，但测试时需要理解：

- `llama_cloud` 当前仍需补装到 `echomem-test`，LlamaParse API 已通过临时 SDK 与真实 Key 验证。
- STM 已支持 SQLite-backed 持久化；UI 当前可恢复最近消息，但尚未提供完整多会话历史浏览。
- LLM 输出尚未实现逐 token 流式渲染。
- KaTeX 增强渲染可能受 Streamlit 沙盒限制；当前标准是可读、不乱码。
- 三框架云端模式主要通过配置控制，UI 暂未提供可视化切换面板。
