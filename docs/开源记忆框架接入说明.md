# 开源记忆框架接入说明

本项目已接入以下开源记忆框架（可选依赖，未安装时自动降级为本地实现）。在 `echomem-test` 环境中，Mem0 / LlamaIndex / Cognee / Chroma 均已安装。

1. `Mem0`：跨会话持久用户事实记忆（用户画像/长期偏好）
2. `LlamaIndex Memory`：文档+对话型知识记忆（知识检索增强）
3. `Cognee`：知识图谱关联记忆（概念关系联想）

## 场景化使用策略（已落地）

当前已在 `OpenSourceMemoryHub.collect_hints()` 中加入”场景识别 + 框架路由”，不同 query 会优先使用不同框架贡献检索扩展词：

1. `preference_alignment`（偏好对齐）
- 触发词示例：`偏好/喜欢/风格/语气/prefer/style`
- 框架优先级：`Mem0 -> LlamaIndex -> Cognee`
- 用途：优先命中用户长期偏好、表达习惯和稳定约束。

2. `session_continuation`（会话续写）
- 触发词示例：`继续/刚才/上文/session/context`
- 框架优先级：`Mem0 -> LlamaIndex -> Cognee`
- 用途：优先补足当前会话上下文，减少”断片感”。

3. `knowledge_qa`（知识问答）
- 触发词示例：`解释/是什么/原理/知识/concept/文档`
- 框架优先级：`LlamaIndex -> Cognee -> Mem0`
- 用途：优先拉取文档型记忆，再用图谱关系补关联知识。

4. `association_brainstorm`（联想发散）
- 触发词示例：`联想/相关/拓展/brainstorm/idea/启发`
- 框架优先级：`Cognee -> LlamaIndex -> Mem0`
- 用途：优先激活概念关联，再补事实与上下文。

5. `general`（默认）
- 框架优先级：`Mem0 -> LlamaIndex -> Cognee`
- 用途：通用查询的平衡策略。

## 代码位置

- 统一编排层：`memory/open_source_memory.py`
- 检索接入点：`agent/tools/memory_search.py`
- 配置开关：`config/loader.py` 中 `MemoryFrameworkConfig`
- 工厂接线：`config/factory.py`

## 默认行为

- 默认开启三个框架开关：
  - `enable_mem0 = true`
  - `enable_llamaindex_memory = true`
  - `enable_cognee = true`
- 若运行环境未安装对应依赖，系统不会报错，会使用本地回退逻辑继续工作。

## 当前信号输出

`OpenSourceMemoryHub.collect_hints()` 会返回 `framework_status`，用于说明每个框架实际贡献的信号来源：

| 框架 | signal_source | 当前输出 |
| --- | --- | --- |
| Mem0 | `mem0_local_profile_index` | 用户偏好、目标、事实型 profile facts |
| LlamaIndex Memory | `llamaindex_memory_buffer` | 基于真实 `llama_index.core.memory.Memory` buffer 的文档命中 |
| Cognee | `cognee_local_concept_graph` | 概念共现图、相关概念、concept edges |

说明：
- 当前已经不是同质词汇 fallback。
- 本轮打通的是 SDK 可用时的本地结构化信号。
- Cognee 持久图谱、Mem0 可配置本地向量后端仍属于后续增强项。

## 配置方式（环境变量）

- `MEMORY_ENABLE_MEM0`
- `MEMORY_ENABLE_LLAMAINDEX_MEMORY`
- `MEMORY_ENABLE_COGNEE`

可选值：`1/true/yes/on` 为开启，其他为关闭。

## 云 API 配置（可选，纯本地路线可忽略）

- Mem0（Platform API）：
  - `MEM0_API_KEY`
- Cognee（Cloud API）：
  - `COGNEE_API_KEY`
  - `COGNEE_BASE_URL`（例如 `https://api.cognee.ai` 或你的 tenant 地址）

说明：
- 该段仅用于切换到云托管模式时参考。
- 本项目当前默认路线是”本地框架 + MiMo 分析”，不依赖这些云端 key。

## 生成用户知识体系与架构图

```bash
python scripts/build_user_knowledge_map.py --user-id u_test --query “总结用户知识体系”
```

输出文件：`docs/user_knowledge_map.md`
包含三框架分析结果与 Mermaid 知识架构图。

## echomem-test 环境部署（本项目推荐）

```bash
# 一键安装 + 回归测试 + 生成示例知识图
bash scripts/deploy_memory_frameworks_local.sh echomem-test

# 独立检查依赖是否齐全
conda run -n echomem-test python scripts/check_memory_frameworks_env.py

# 在指定环境运行工作流
conda run -n echomem-test python scripts/workflow.py
```

说明：
- 当前机器未安装 Docker 时，Mem0 Server 容器化路径会跳过，采用 Python SDK 本地模式接入。

## 纯本地路线 + MiMo 分析

- 当前 `memory/open_source_memory.py` 已按纯本地模式实现：
  - 不依赖 Mem0/Cognee 云端 API key
  - 使用本地框架可用能力与本地回退逻辑生成记忆提示
- 知识体系总结由 MiMo 执行：
  - 从统一配置对象读取 MiMo 配置；真实 Key 和 API 地址推荐放在 `.env` 或运行环境变量中
  - 输出字段：`open_source_memory.mimo_analysis`
- UI 已集成框架结果面板：
  - 在 `ui/app.py` 的「记忆框架」Tab 查看 Mem0/LlamaIndex/Cognee 信号、MiMo 分析文本、Mermaid 知识图

## 知识图脚本增强

```bash
conda run -n echomem-test python scripts/build_user_knowledge_map.py \
  --user-id demo_user \
  --query “总结用户知识体系” \
  --max-memories 300 \
  --strict-user-scope
```

- `--strict-user-scope`：优先仅使用 `[user=<id>]` 标记的记忆，减少跨用户污染
- 输出仍为：`docs/user_knowledge_map.md`
